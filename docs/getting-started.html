Volume 1

Getting Started

Install it, put a bar on screen by hand, then do the same thing from AppGen in four steps. Twenty minutes, no prior knowledge assumed.

5 files to install1 DLL to ship4 demos

StartWhat this is

ClaCommandBar puts Codejock-style command bars, ribbons and popup menus on a Clarion window. It is three layers, and you can stop at whichever one suits you.

Templates

Fill in prompts in AppGen; the wiring is generated. Most people never go below this.

↓  generates calls to
CommandBarClass

An ABC-style Clarion class. Hand-written code talks to this.

↓  calls, by pinned ordinal
commandbar.dll

A flat __stdcall C API over a Direct2D engine. 32-bit, static CRT, no VC++ redistributable.

The engine draws everything itself, so a bar looks the same on Windows 7 and Windows 11 rather than inheriting whatever the OS thinks a toolbar should be.

StartInstalling

Run clarion\install.bat. It copies five files and registers the template:

ClaCommandBar.tpl   ->  accessory\template\win
CommandBar.inc      ->  accessory\libsrc\win
CommandBar.clw      ->  accessory\libsrc\win
commandbar.lib      ->  accessory\lib  AND  accessory\libsrc\win
commandbar.dll      ->  accessory\bin

Close the IDE first, and reopen it after

AppGen caches a parsed copy of the template. An IDE that was open when you installed keeps serving the old one, which looks exactly like the install not working.

Ship commandbar.dll beside your EXE. That is the only runtime file.

StartYour first bar, by hand

No templates involved — this is the whole program:

  PROGRAM
  PRAGMA('link(commandbar.lib)')
  INCLUDE('EQUATES.CLW'),ONCE
  INCLUDE('CommandBar.inc'),ONCE
  MAP
  END

CB    CommandBarClass
bar   SIGNED

CMD:New   EQUATE(1001)
CMD:Open  EQUATE(1002)

Win WINDOW('Hello'),AT(,,320,200),SYSTEM,GRAY,RESIZE,FONT('Segoe UI',9),TIMER(10)
    END

  CODE
  OPEN(Win)
  IF ~CB.Init(Win, CBS:Tooltips)             ! starts the DLL, makes a manager
    MESSAGE('commandbar.dll did not start.')
    RETURN
  END
  CB.SetTheme(CBT:SteelBlue)

  bar = CB.AddBar('Standard', CBD:Top)
  CB.AddButton(bar, CMD:New,  '&New')
  CB.AddButton(bar, CMD:Open, '&Open')
  CB.AddSeparator(bar)
  CB.AddButton(bar, 0, 'Does nothing')       ! command id 0 raises nothing

  ACCEPT
    CASE EVENT()
    OF EVENT:Timer
      LOOP WHILE CB.TakeOne()                ! drain the queue
        CASE CB.LastCmd
        OF CMD:New  ; Win{PROP:Text} = 'New'
        OF CMD:Open ; Win{PROP:Text} = 'Open'
        END
      END
      CYCLE
    OF EVENT:Sized
      CB.Layout()
    END
  END
  CB.Kill()
  CLOSE(Win)

Three things that are not optional

PRAGMA('link(commandbar.lib)') binds the imports.

A TIMER on the window drives the pump. Without one, nothing you click is ever delivered — the bars draw and respond to the mouse, but your code never hears about it.

EVENT:Sized has to reach CB.Layout(), or the bars keep the size they had when the window opened.

StartThe same thing, with the template

  1. Open the procedure in AppGen and add the extension ClaCommandBar — command bars and menus on this window. (On an APPLICATION frame, use the FRAME one instead.)
  2. Go to the Bars tab, pick a toolbar from the drop and press Add this toolbar. That fills in the bar, its items, the icons, the tooltips and the shortcuts.
  3. Generate and compile. You have a working toolbar before writing a line.
  4. Open the embed point for a command id and put your code there.

Icons: name them plainly, add them to the project

Write NEW.ICO, not a path. An image added to the application’s project is linked into the EXE, and Clarion names that resource after the file — NEW.ICO becomes NEW_ICO — which is where the manager looks first. A loose copy beside the EXE, or in an images folder next to it, is found too.
