ConceptsManagers, containers and items

One manager per window — CB.Init makes it, CB.Kill takes it down. A container is anything that holds items: a docked bar, a floating bar, a popup menu, or a ribbon group. An item is a button, a toggle, a separator, an edit box. Both come back as integer ids, and you keep the ones you will need again.

Command ids are yours

Every item carries a command id you choose. Clicking it queues an event carrying that id; an id of 0 means the item raises nothing, which is what separators and labels use. Two items may share an id — a toolbar button and a menu row for the same command usually should, and then EnableCmd greys out both at once.

ConceptsThe event pump

Nothing is dispatched behind your back. The engine never calls into your code — it queues events, and you drain the queue:

  OF EVENT:Timer
    LOOP WHILE CB.TakeOne()          ! returns 0 when the queue is empty
      CASE CB.LastCmd
      OF CMD:Save ; DO SaveRoutine
      END
    END
    CYCLE

TakeOne fills LastItem, LastCmd, LastEvent and LastParam, then calls the virtual TakeCommand / TakeToggled methods. Deriving is the tidier way once a window has more than a handful of commands:

MyBar  CLASS(CommandBarClass)
TakeCommand PROCEDURE(LONG cmd, SIGNED item),BYTE,DERIVED
       END

MyBar.TakeCommand PROCEDURE(LONG cmd, SIGNED item)
  CODE
  CASE cmd
  OF CMD:Save ; DO SaveRoutine
  OF CMD:Exit ; POST(EVENT:CloseWindow)
  END
  RETURN PARENT.TakeCommand(cmd, item)

The pump needs a TIMER

Bars with no timer draw, hot-track and open their menus — and never deliver a thing. It is the single most common reason a bar “does nothing”.

ConceptsRows, offsets and docking

Bars dock to an edge on a row: row 0 is nearest the edge, row 1 sits under it. Two bars on the same row sit side by side in offset order. A user with a gripper can drag a bar to another edge, into another row, or tear it off into a floating caption frame.

A ribbon always takes a row to itself. It is a full-width band with tabs across it, so sharing a row would leave nothing for its neighbour — put a menu bar and a ribbon both on row 0 and the ribbon moves down to row 1 rather than swallowing the menu.

How toBuilding a ribbon

A bar of tabs; each tab a row of groups; each group full of ordinary items.

rib = CB.AddRibbon('Ribbon', CBD:Top)
tab = CB.AddRibbonTab(rib, '&Home')

grp = CB.AddRibbonGroup(tab, 'Clipboard')
CB.AddLargeButton(grp, CMD:Paste, 'Paste', iPaste)   ! the big one
CB.AddButton(grp, CMD:Cut,  'Cut',  iCut)            ! small ones stack beside it
CB.AddButton(grp, CMD:Copy, 'Copy', iCopy)

grp = CB.AddRibbonGroup(tab, 'Styles')
gal = CB.AddGallery(grp, CMD:Style, 4, 62, 54)       ! columns, cell w, cell h
CB.AddGalleryCell(gal, iNew,  'Normal')
CB.AddGalleryCell(gal, iOpen, 'Heading')
CB.SetGallerySel(gal, 0)

CB.MinimizeRibbon(rib, 1)                            ! start collapsed

AddLargeButton (or the CBIS:TextBelow style) makes the big image-over-text button a group leads with; everything beside it stacks three-deep in small rows. A gallery takes a column of its own, and is shrunk to fit if it asks for more height than the group has.

Collapsing is built in: a chevron at the end of the tab strip, a double-click on a tab, or MinimizeRibbon.

How toTaking over the menu

MirrorMenu reads the window’s MENUBAR at run time and rebuilds it as a command bar — same order, same nesting, separators kept, KEY() attributes turned into a shortcut column, disabled items still disabled. Choosing a mirrored row POSTs EVENT:Accepted to the original ITEM, so every menu embed you already wrote goes on running.

Win WINDOW('Mirrored'),AT(,,420,260),SYSTEM,GRAY,RESIZE,TIMER(10)
      MENUBAR
        MENU('&File')
          ITEM('&New'),USE(?MNew),KEY(CtrlN)
          ITEM('E&xit'),USE(?MExit)
        END
      END
    END

  CODE
  OPEN(Win)
  CB.Init(Win, CBS:Tooltips + CBS:MenuIcons)
  CB.MirrorMenu(CB.AddMenuBar(), 1)      ! 1 = take the real menu off the window

  ACCEPT
    CASE EVENT()
    OF EVENT:Timer ; LOOP WHILE CB.TakeOne() . ; CYCLE
    END
    CASE ACCEPTED()
    OF ?MNew                             ! your ORIGINAL embed code still runs
      Win{PROP:Text} = 'New, from the mirrored row'
    OF ?MExit
      POST(EVENT:CloseWindow)
    END
  END

And the toolbar

The same trick on the row of buttons. Every BUTTON, CHECK, ENTRY, COMBO and PROMPT in the TOOLBAR becomes a bar item carrying its ICON(), its TIP() and its disabled state.

tb = CB.AddBar('Tools', CBD:Top)
CB.SetBarDock(tb, CBD:Top, 1, 0)         ! its own row, under the menu
n  = CB.MirrorToolbar(tb, 1)             ! 1 = hide the real TOOLBAR

Why this matters on an MDI frame

Opening a child window makes Clarion hide the frame’s toolbar, build a second ClaToolBar for the merged one, and swap them. Mirror the toolbar, hide the real one, and there is nothing left on screen for that to disturb.

What mirroring cannot see

On an MDI frame it mirrors the frame’s own menu. A menu an MDI child merges in is not reachable: the child’s controls live on the child’s thread and never enter the frame’s control list, and although the frame’s HMENU really does grow, Clarion owner-draws its menus so the items come back with no text at all.

Use NOMERGE on the children, or leave the real menu attached.

How toLeaving room for the bars

!  On an APPLICATION FRAME the frame's own toolbar and MDI client are moved
!  clear of the bars automatically.  A plain WINDOW positions its own
!  controls, so re-fit whatever should fill what the bars left:
  OF EVENT:Sized
    CB.Layout()
    CB.FitControl(?Browse:1, 4, 4)       ! 4px margin

!  A WINDOW with a STATUS bar has no MDI client to measure from, so say
!  how tall it is and no bar will cover it:
  CB.HostReserveBottom(23)

CB_GetClientRect — ClientX/Y/Width/Height on the class — reports what the bars left over, in pixels. On a frame the host’s own children are moved for you; on a plain window you place your own controls.

How toSliders, spins and progress

One idea wearing three faces: a value between two bounds.

zoom = CB.AddSlider(bar, CMD:Zoom, 25, 400, 100, 130)   ! lo, hi, value, width
page = CB.AddSpin(bar, CMD:Page, 1, 9999, 1, 60)
busy = CB.AddProgress(bar, 0, 100, 0, 130)

!  in the pump - the value arrives in LastParam
  OF CBE:ValueChanged
    CASE CB.LastCmd
    OF CMD:Zoom ; Scale = CB.LastParam
    END

!  the progress bar raises nothing; drive it yourself
CB.SetItemNumber(busy, done * 100 / total)

A drag fires on every step

Keep that handler cheap — store the value and do the heavy work afterwards, or a slider repaints your report once per pixel.

How toRemembering bar positions

One INI entry holds which edge each bar is on, which row, the order within it, whether it is showing, where a floating one sits, and whether a ribbon is collapsed.

!  after the bars are built
CB.RestoreLayoutFrom('.\MyApp.INI', 'CommandBars')

!  before the window closes
CB.SaveLayoutTo('.\MyApp.INI', 'CommandBars')

Bars are matched by name, so adding or removing one in a later release never hands an old position to the wrong bar; a name it does not recognise is ignored. LayoutText() and RestoreLayout() hand you the blob directly if you would rather keep it in a user record.

How toTheming

CB.SetTheme(CBT:Office2016)              ! start from one of eleven
CB.SetAccent(COLOR:Navy)                 ! re-derive the palette from an accent
CB.SetColor(CBC:BarBack, 00F5F5F5h)      ! or override single slots
CB.SetMetric(CBM:IconSize, 20)
CB.SetMetric(CBM:LargeIcon, 32)
CB.Redraw()

Eleven themes, each derived from a handful of seed colours; 38 colour slots, four font roles and thirteen metrics on top. The full tables are in the Reference.

Clarion notesWhy Clarion behaves as it does

Most of the surprises in this library are not the library. They are worth knowing before you go looking for a bug that is not there.

What you seeWhat is actually happening
A mirrored bar comes out emptyMenu controls live in four equate ranges. A WINDOW numbers named ones upward from 1 and unnamed ones upward from 32768; an APPLICATION frame numbers named ones downward from -1 and unnamed ones downward from 32767, and answers LASTFIELD() = 0. Call MenuReport() — it says which it found
The frame’s toolbar disappears when a procedure opensNOMERGE on the frame’s own TOOLBAR means “do not carry this into the merge”. Put NOMERGE on children, never on the frame’s toolbar
A child’s merged menu never appears on the mirrored barIt cannot. The child’s controls are on the child’s thread, and the merged HMENU is owner-drawn — every item reads back MFT_OWNERDRAW with cch = 0 and no text
A toolbar flickers when an MDI child opens or closesClarion swaps the frame’s toolbar for a merged one and back, so that strip is painted twice either way. Mirroring the toolbar and hiding the real one removes it
PROP:Hide does nothing to a MENUBARIt is a real Win32 menu on the frame, not a control. SetHostMenu(0) detaches it with SetMenu(), and puts it back when the window closes

When a frame child sits in the wrong place

Set CB_HOSTLOG=1 in the environment and run again. Every move of the host’s own children is traced to %TEMP%\cbhost.log — HOOK, CHANGING and APPLY lines with the rect asked for and the rect given.

Clarion notesWhen it misbehaves

What you seeWhat it is
No bars at allThe DLL is not beside the EXE, or Init returned 0 — check its result
Bars appear, clicks do nothingNothing is pumping. The window needs a TIMER and the timer needs to reach TakeOne
Bars do not resize with the windowEVENT:Sized is not reaching Layout()
Icons missingThe images are not in the project and not beside the EXE. NEW.ICO is looked up as the resource NEW_ICO
A slider, spin, progress or gallery draws as a plain button with its text on itAn old commandbar.dll: CB_AddItem used to reject any type above CBI_SPACE and hand back a button. The DLL alone fixes it — nothing to regenerate
A slider moves but nothing happens in a generated appOlder generated code: the pump only handled CBE:Command. It takes CBE:ValueChanged too now, so regenerate
Unresolved External CB_...A second commandbar.lib is shadowing the installed one — check your own application folder, and accessory\libsrc\win
AppGen hangs on a template buttonA template group returned text where a number was expected — '0' is true to #IF and to #LOOP,WHILE
