Template Guide

The four templates, every tab and prompt, the presets, the embed points, and what the generator actually writes into your procedure.

TemplatesThe four templates

TemplateKindPut it onWhat it adds
CommandBarGlobalExtensionthe application, oncedefaults every window inherits — theme, colours, icon sizes
CommandBarOnWindowExtensionany procedure with a windowbars, ribbons, menus and items on that window
CommandBarFrameExtensionan APPLICATION frameeverything above, plus mirroring the frame's MENUBAR and TOOLBAR
CommandBarControlControla window, from the toolboxdrops a REGION and lands a bar exactly on it

They share their tabs, so everything below applies wherever you find it. Only the frame template has Menu and toolbar; only the control template can land a bar on its own region.

Names tie it together. A bar is named on the Bars tab; an item names that bar in Put it in. The same goes for menus and ribbon groups. Each name becomes a variable in the generated source — CBBar:1:Standard, CBMnu:1:RowMenu — which is what you pass when you call the class yourself from an embed.

A name that resolves to nothing is a generate-time error

Not a silently missing item. If you rename a bar, the items pointing at it stop the generate until you rename them too.

TemplatesPresets

Three buttons fill the lists in for you. What they make is ordinary entries afterwards — rename them, reorder them, delete the ones you do not want.

Ribbon tab

The ribbon from CommandBarShowcase, plus the two things only a ribbon can do: Home (Clipboard, Font, a Styles gallery, Editing), Insert (Pages, Illustrations, Links) and View (Show, and Zoom with a slider).

Menus tab

One of File, Edit, Browse row, View or Help.

Each press starts a new bar on the first row of that edge nobody is using, and command ids carry on from the highest already in use — so nothing a preset makes collides with what you added yourself. Press one twice and you get Standard2.

What an item does

ActionGenerates
Embed code onlynothing — you write it
Call a procedureThatProcedure(parms)
Do a routineDO ThatRoutine
Emulate a controlPOST(EVENT:Accepted, ?ThatControl)
Post an eventPOST(EVENT:Whatever, ?Control)
Close the windowPOST(EVENT:CloseWindow)

Emulate a control saves the most work: point a bar button at a BUTTON or a menu ITEM already on the window and its existing embed code runs, untouched.

A gallery’s cells

One line, Text=Image separated by pipes, in the order they read — the image names come from the Images tab:

Normal=New|Heading=Open|Title=Save|Quote=Print

Leave the =Image off a cell that has no picture. Clicking a cell raises the item’s command with the cell number (0 first) in LastParam.

TemplatesEmbed points

Ten, each existing in all three extensions. The per-command one is the one you will use most: every distinct command id gets its own embed, so you are not writing a CASE by hand.

EmbedWhen it runs
this command was chosenone per command id — the workhorse
before the bars are createdanything that must happen before Init’s work
after the bars are builtadd items the prompts cannot describe
a toggle or check box flippedLastParam is 1 when on
a menu is about to openrebuild a Recent list before it shows
an edit box was committedItemValue(item) has the text
a combo selection changedLastParam is the 0-based index
a colour button changedLastParam is the colour
a ribbon tab was switchedLastParam is the tab
an item was right-clickedhang a context menu off it

The generated object is called CommandBar, so inside an embed you have the whole class: CommandBar.SetItemEnabled(CBItm:1:7, 0).

TemplatesWhat gets generated

!  what the template writes into your procedure, trimmed:
CBBar:1:Standard = CommandBar.AddBar('Standard',CBD:Top,6)
CommandBar.SetBarDock(CBBar:1:Standard,CBD:Top,0,0)
CBItm:1:1 = CommandBar.AddItem(CBBar:1:Standard,CBI:Button,1000,'&New',CBImg:1:New)
CommandBar.SetItemTooltip(CBItm:1:1,'New (Ctrl+N)')

!  and the dispatch, one branch per distinct command id:
LOOP WHILE CommandBar.TakeOne()
  CASE CommandBar.LastEvent
  OF CBE:Command
  OROF CBE:ValueChanged
    CASE CommandBar.LastCmd
    OF 1000
      !  <-- your embed for command 1000 runs here
    END
  END
END

Regenerate versus rebuild

Template changes only reach you on the next generate. Engine changes are in the DLL and reach you on the next run. When something is fixed “in the DLL alone”, copying the new commandbar.dll beside your EXE is the whole fix.
