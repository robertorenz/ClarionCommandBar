ClarionCommandBarClass

Declared in CommandBar.inc, implemented in CommandBar.clw. Every method is VIRTUAL, so deriving works the ABC way. Each entry carries a worked line of Clarion, and the tables are read out of the header — they cannot drift from the code.

CB   CommandBarClass                     ! that is the whole declaration

HostReserveBottomHostReserveBottom(SIGNED px),PROC,VIRTUAL

A strip along the bottom the HOST paints itself, that no bar may use. On an APPLICATION frame it is measured automatically - the frame stops its MDI client short of the bottom and that gap IS the status bar - so nothing needs setting. A plain WINDOW with a STATUS bar has no such child to measure, so give it the height in PIXELS and a bottom, left or right bar will stop above the status bar instead of covering it. Pass -1 to go back to measuring.

The event pump

TakeOneTakeOne(),BYTE,PROC ! one event into Last*, 0 = queue empty

event pump. Two ways to use it, pick one: 1. hand-coded: LOOP WHILE CB.TakeOne() ... read SELF.Last* 2. derived: CB.TakeEvent() and override the Take... methods TakeEvent is TakeOne in a loop with a CASE on the event type, so never mix the two on the same object - the first one to run drains the queue and the other sees nothing.

  OF EVENT:Timer
    LOOP WHILE CB.TakeOne()               ! 0 when the queue is empty
      CASE CB.LastCmd
      OF CMD:Save ; DO SaveRoutine
      END
    END
    CYCLE

Ordinals are a contract

The Clarion import library binds by ordinal, not by name. The numbers in commandbar.def are never renumbered and never reused; new exports get the next free number, appended. Renumbering one silently points every existing EXE at the wrong function.

Reserving space from the host

On an APPLICATION frame the host lays its own toolbar and MDI client out against the full client area. This moves them clear of the bars.

CB_SetReserveSpace@79void CB_SetReserveSpace(HCB cb, int mode);

CB_GetClientRect reports what the bars left over, but the HOST does not read it. A Clarion APPLICATION frame lays its own ClaToolBar and MDIClient out against the FULL client area, so docked bars end up drawn on top of them. With reserving on, the manager moves the host's own child windows out of the strips the bars took: a top band like a toolbar is shifted down keeping its height, and a filler like the MDI client is shifted and shortened, keeping whatever inset the host left for a status bar. mode 1 = always, 0 = never, -1 = AUTO (the default): on when the host has an MDIClient or a ClaToolBar of its own, off otherwise - a plain window positions its own controls, so use CB_GetClientRect and move them yourself there.
